1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
CloudPath AI is an integrated meteorological intelligence system engineered to
address one of the most critical challenges in atmospheric computing: combining
localized ground-station sensor observations with space-borne geostationary satellite
imagery for next-hour convective rainfall prediction and regional cloud motion tracking.

The system incorporates:
  1. High-frequency ground-sensor meteorological modeling for quantitative
     precipitation forecasting (next-hour rainfall occurrence and volume).
  2. Earth-observation satellite image processing on raw NetCDF-4 datasets from
     ISRO's INSAT-3DS Imager to identify cloud structures and quantify regional coverage.
  3. Computer vision and spatial graph matching (Hungarian algorithm) to track
     individual cloud formations across space and time, extracting movement vectors,
     meteorological bearings, and physical speeds in km/h.
  4. An operational web dashboard and REST API providing interactive forecasting
     and situational awareness without external web framework dependencies.

2. SYSTEM ARCHITECTURE & DATA PIPELINE
--------------------------------------------------------------------------------
The architecture is structured into decoupled, modular pipelines:

  [Ground Weather Sensors] (2009–2020)
       │
       ▼
  [Phase 1: Feature Engineering & Preprocessing] (96,431 records, 25 features)
       │
       ▼
  [Phase 2: Dual-Model Machine Learning Pipeline]
       ├── XGBoost Classifier (Rain Status: 0 / 1 + Probability)
       └── XGBoost Regressor  (Precipitation Amount: mm in next hour)
  
  [INSAT-3DS Geostationary Satellite Data] (1–31 July 2025, 31 NetCDF files, ~30 GB)
       │
       ▼
  [Phase 3: Sub-region Extraction] (Bengaluru domain: 162 × 159 grid, ~650 × 650 km, 1,448 frames)
       │
       ▼
  [Phase 4: Cloud Motion Tracking Engine]
       ├── 8-Connected Component Segmentation (16,321 cloud objects)
       ├── Bounding-Box IoU & Centroid Cost Matrix
       ├── Hungarian Assignment Algorithm (11,697 frame matches)
       └── Geospatial Scale Conversion (4.079 km/row, 4.055 km/col -> km/h speed)

  [Phase 5 & 6: Integration, REST API & Web Dashboard]
       ├── Prediction Engine (Strict 25-feature inference & validation)
       ├── Zero-Dependency Python HTTP Server (dashboard_app.py)
       └── Responsive Dark-Mode Single Page Application (SPA)

4. DATASET SPECIFICATIONS
--------------------------------------------------------------------------------
A. Ground Meteorological Dataset (Bengaluru Weather):
   - Observations    : 96,431 continuous hourly records
   - Temporal Range  : 2009-01-01 00:00:00 to 2020-01-01 22:00:00 UTC
   - Parameters (25) : Temperature (max/min/current), Dew Point, Humidity, Pressure,
                       Cloud Cover, Wind Speed, Wind Gust, Wind Direction, UV Index,
                       Sun Hours, Visibility, Precipitation, Cyclical Temporal Features.
   - Rain Imbalance  : 87.7% No Rain (84,603 hrs), 12.3% Rain (11,828 hrs).

B. Satellite Earth Observation Dataset (INSAT-3DS):
   - Instrument      : INSAT-3DS IMAGER NICES Cloud Mask Ver02 (ISRO-DOS / NRSC)
   - Resolution      : 0.04° × 0.04° (~4 km at equator), WGS 84 Projection
   - Raw Format      : NetCDF-4 (31 daily volumes, ~950 MB each, total ~30 GB)
   - Temporal Range  : 2025-07-01 00:30:00 to 2025-07-31 23:30:00 UTC (1,448 observations)
   - Bounding Box    : Lat [9.986°N, 15.939°N], Lon [74.604°E, 80.564°E]
   - Mask Encoding   : 0 = Clear Sky, 1 = Cloud Covered, NaN = Space/Fill.

5. DETAILED SUMMARY OF ALL SIX PHASES
--------------------------------------------------------------------------------

PHASE 1: Weather Dataset Preprocessing and Exploratory Data Analysis (EDA)
  - Cleaned missing values, removed uninformative columns, verified chronological order.
  - Engineered cyclical temporal features (hour, day, month, season encoding).
  - Created strict prediction targets without data leakage:
      * rain_status: Binary target (1 if next_hour_rainfall > 0 else 0)
      * next_hour_rainfall: Continuous rainfall amount shifted by -1 hour.
  - Generated 11 comprehensive EDA charts in 'eda_graphs/'.

PHASE 2: Machine Learning Model Development & Benchmarking
  - Enforced chronological train-test split (80% train = 77,144 rows; 20% test = 19,287 rows).
  - Never shuffled time-series records to prevent temporal data leakage.
  - Trained and tuned 4 Classifiers and 4 Regressors.
  - Selected XGBoost as champion for both classification and regression.
  - Saved model bundles: 'rainfall_classifier.pkl' and 'rainfall_regressor.pkl'.

PHASE 3: Satellite NetCDF Data Processing & Regional Extraction
  - Unpacked and verified 31 INSAT-3DS ZIP archives into 'satellite_nc/'.
  - Extracted 162 × 159 pixel Bengaluru regional domain across all 1,448 time slots (July 1–31, 2025).
  - Handled large NetCDF files sequentially to prevent RAM exhaustion.
  - Processed valid observations, identified 40 satellite eclipse/calibration missing slots (97.3% completeness).
  - Mean cloud coverage: 75.04% (Southwest Monsoon period).
  - Saved compressed stack 'bengaluru_cloudmask_series.npz' and summary CSV.

PHASE 4: Multiple Cloud Detection and Movement Tracking
  - Implemented 8-connected component segmentation for cloud formation detection (16,321 objects).
  - Extracted centroids, bounding boxes, areas, and cloud type flag classifications.
  - Constructed cost matrix combining normalized centroid displacement and IoU overlap.
  - Solved global optimal assignment using the Hungarian algorithm (linear_sum_assignment).
  - Built 4,624 cloud tracks (2,831 multi-frame tracks, 1,064 tracks spanning >= 5 frames).
  - Derived actual geospatial resolution: 4.079 km/row (N-S), 4.055 km/col (E-W).
  - Computed physical velocities (km/h) and meteorological bearings (0° to 360°).
  - Saved tracking outputs: 'cloud_tracking_results.csv', 'cloud_tracks.csv',
    'cloud_movement_summary.csv', and 'cloud_trajectories.csv'.

PHASE 5: System Integration & Temporal Auditing
  - Conducted rigorous temporal audit: documented that ground weather (2009–2020) and
    satellite imagery (July 2025) do not overlap temporally.
  - Established ethical academic protocol: ML models predict on valid weather vectors,
    while satellite observations operate in parallel as live situational context.
  - Built unified prediction engine 'prediction_engine.py'.
  - Created operational CLI dashboard 'cloudpath_dashboard.py'.

PHASE 6: Verification, Web Dashboard & Final Demonstration
  - Built automated 13-point test suite 'test_all_modules.py' (100% pass rate).
  - Implemented modern, dark-mode single-page web dashboard in 'dashboard_app.py'.
  - Created REST API endpoints for live status, observations, predictions, and images.
  - Validated socket-free HTTP test runner 'test_web_handler.py'.

7. ACADEMIC INTEGRITY & LIMITATIONS
--------------------------------------------------------------------------------
  1. Temporal Disjunction:
     The ground meteorological records (2009–2020) and satellite data (July 2025)
     originate from different observation epochs. Fabricating an artificial alignment
     would violate scientific integrity. The project correctly treats satellite motion
     as real-time observational context and demonstrates how future contemporaneous data
     can be fed into the architecture.
  2. Satellite Eclipse Pauses:
     40 half-hour observation slots were missing in the satellite feed due to scheduled
     spacecraft eclipse and sensor calibration routines (97.3% data completeness).
  3. Spatial Extent:
     Ground weather models are trained for point-location weather stations in Bengaluru;
     satellite tracking operates over a ~650 × 650 km mesoscale regional window.
